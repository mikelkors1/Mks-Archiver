## О проекте

**MksArchiver** — консольный архиватор собственного формата (`.mks`), написанный на C#. Поддерживает создание архивов со сжатием, извлечение файлов, добавление новых файлов в существующий архив, удаление файлов из архива и просмотр содержимого — без сторонних зависимостей, поверх бинарного формата, спроектированного с нуля.

## Возможности

| Команда | Описание |
|---|---|
| `--create` | Создать новый архив из одного или нескольких файлов |
| `--extract` | Извлечь все файлы из архива, либо только указанные |
| `--append` | Добавить новые файлы в существующий архив |
| `--delete` | Удалить один или несколько файлов из архива (или архив целиком, если файлы не указаны) |
| `--list` | Показать содержимое архива: имена, оригинальный и сжатый размер файлов |
| `--help` | Показать справку по командам |

> Команда `--concatenate` (`-A`, объединение архивов) в текущей версии **не реализована**.

## Формат архива

Архив `.mks` устроен как последовательность трёх блоков:

```
┌─────────────────────┐
│   Заголовок          │  magic number, версия, кол-во файлов
├─────────────────────┤
│   Таблица метаданных │  имя, размер, сжатый размер, offset — для каждого файла
├─────────────────────┤
│   Блок данных         │  сжатые байты содержимого файлов
└─────────────────────┘
```

Сжатие данных выполняется через `DeflateStream`. Offset каждого файла в блоке данных — относительный, вычисляется динамически при чтении, что делает формат устойчивым к изменению размера таблицы метаданных.

## Использование

```bash
# Создать архив
dotnet run -- --create archive.mks file1.txt file2.mp4

# Посмотреть содержимое
dotnet run -- --list archive.mks

# Извлечь всё
dotnet run -- --extract archive.mks

# Извлечь конкретные файлы
dotnet run -- --extract archive.mks file1.txt

# Добавить файл в существующий архив
dotnet run -- --append archive.mks file3.pdf

# Удалить файл из архива
dotnet run -- --delete archive.mks file1.txt

# Удалить архив целиком
dotnet run -- --delete archive.mks
```

## Технические детали

- Целевая платформа: .NET
- Формат чисел в архиве — little-endian (стандартное поведение `BinaryWriter`/`BinaryReader`)
- Все операции изменения архива (`--append`, `--delete`) выполняются атомарно: сначала собирается временный файл `*.tmp`, и только после успешной записи он замещает оригинальный архив
